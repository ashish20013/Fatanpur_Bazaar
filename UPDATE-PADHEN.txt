फतनपुर बाज़ार — इस अपडेट में क्या बदला (25 सितंबर 2026)
=========================================================

A. आपके सात बदलाव
------------------
1. हेडर के नीचे वाला मोटा हरा डिब्बा हटा दिया — अब सामान सीधे ऊपर दिखता है।
   (फ़ोन का नंबर फ़ुटर में पहले से है, इसलिए कुछ खोया नहीं।)

2. लोकेशन अब अपने आप ढूंढी जाती है। पहली बार आने पर साइट फ़ोन से जगह लेती है,
   सबसे पास का गाँव निकालती है, और फिर पूछती है — "क्या आप यहीं हैं?"
     [हाँ, यहीं भेजें]  [नहीं, दूसरी जगह]
   पूछना ज़रूरी है: फ़ोन बताता है आप कहाँ हैं, पर सामान शायद माँ-बाप के गाँव भेजना हो।
   ⚠️ ब्राउज़र का अपना "अनुमति दें?" वाला डिब्बा कोई भी वेबसाइट हटा नहीं सकती — वो
      ब्राउज़र का नियम है। हमने बस इतना किया कि एक ही बार पूछा जाए, सही समय पर, और
      मना करने पर दोबारा तंग न किया जाए। मना करने पर साइट पहले जैसी चलती रहती है।

3. दुकान बंद हो तब भी ऑर्डर लिया जाएगा। ग्राहक को साफ़ दिखेगा:
   "अभी दुकान बंद है — ऑर्डर ले लिया जाएगा और आपका सामान सुबह 7:00 तक पहुँच जाएगा।"
   रात 11 बजे का ऑर्डर असली ऑर्डर है; मना करने पर वो ग्राहक कल किसी और के पास जाता है।
   (Settings → accept_orders_when_closed = 0 करने पर पुराना बर्ताव वापस आ जाएगा।)

5. कम से कम ऑर्डर की सीमा हटा दी — ₹25 का ऑर्डर भी चलेगा।
6. डिलीवरी चार्ज हटा दिया — कहीं भी, कितना भी छोटा ऑर्डर हो। बिल में "मुफ़्त" लिखा आएगा।
   (गाँव और ज़ोन, दोनों जगह के चार्ज भी 0 कर दिए, वरना वो चुपचाप ऊपर लग जाते।)

7. UPI से भुगतान अब एक टैप में:
     • QR स्कैन करें / ऐप खोलें → भुगतान करें
     • बड़ा हरा बटन: "मैंने भुगतान कर दिया" → ऑर्डर तुरंत पक्का
     • UTR नंबर अब ज़रूरी नहीं (नीचे छोटी लाइन में, चाहें तो दे दें — जाँच जल्दी होती है)

   ⚠️ और एक बड़ी ख़राबी पकड़ी गई: QR कभी दिखता ही नहीं था। सर्वर तस्वीर की जगह
      टेक्स्ट भेज रहा था, इसलिए ग्राहक को टूटी तस्वीर का डिब्बा दिखता था। ठीक कर दिया —
      अब असली QR आता है।

   ⚠️ पूरी तरह "अपने आप" भुगतान पक्का होना सीधे UPI से मुमकिन नहीं है — बैंक वेबसाइट को
      बताता ही नहीं कि पैसा आया। इसलिए ऑर्डर तुरंत पक्का होता है (₹2000 तक) और पैसा आपको
      अपने बैंक ऐप में देख कर एडमिन पैनल में Verify दबाना होता है। सच में अपने आप चाहिए तो
      पेमेंट गेटवे (Razorpay/Cashfree) चाहिए — उसका कोड पहले से लिखा और बंद रखा है,
      पर उसके लिए आपका KYC और ~2% फ़ीस लगेगी। कहिए तो चालू कर दूँ।

0. "Database is behind the code" वाली दिक़्क़त ख़त्म
---------------------------------------------------
हर बार नया कोड आने पर आपको `npm run db:migrate` याद रखना पड़ता था, और भूलने पर API
चालू ही नहीं होता था। अब:

  • development में (आपका लैपटॉप) — API ख़ुद बाक़ी migrations लगा लेता है और बता देता है
    कि क्या लगाया। `npm run dev:api` बस चल जाएगा, कुछ याद रखने की ज़रूरत नहीं।
  • production में (असली साइट) — उल्टा होता है: वो रुक जाता है और नाम बता देता है।
    चलती दुकान का डेटाबेस अपने आप नहीं बदलना चाहिए — वो deploy का फ़ैसला है, एक बार,
    बैकअप के साथ।

1. हेडर के नीचे की कैटेगरी पट्टी अब रंगीन है
---------------------------------------------
बीस कैटेगरी के लिए बीस अलग रंगीन चित्र बनाए गए — किराना की टोकरी, फल-सब्ज़ी का टमाटर,
मिठाई की थाली, दवाई का कैप्सूल, भाड़ा गाड़ी की गाड़ी, खेती का ट्रैक्टर, वग़ैरह।
पहले बीस एक जैसे हल्के चिह्न थे जिनमें अंतर करने के लिए नाम पढ़ना पड़ता था।

पट्टी अब **दाएँ से बाएँ बहुत धीरे सरकती है** (एक कैटेगरी को स्क्रीन पार करने में
क़रीब 8 सेकंड) **और आप उसे कभी भी ख़ुद उँगली से खिसका सकते हैं**।

पहले वो CSS से सरकाई जा रही थी और उसका डिब्बा बंद (overflow hidden) रखना पड़ता था —
यानी दिखती चलती-फिरती थी पर उँगली से खिसकती नहीं थी। अब वो असली स्क्रॉल को सरकाती है,
इसलिए पहली ही स्वाइप काम करती है, सस्ते फ़ोन पर भी।
  • उँगली रखते ही रुक जाती है (ताकि टैप वहीं लगे जहाँ आपने निशाना लिया)
  • एक बार आपने ख़ुद खिसकाया — वो अपने आप सरकना बंद कर देती है, अब पट्टी आपकी है
  • सूची दो बार बनी है, इसलिए घूम कर वापस आते वक़्त कहीं झटका नहीं लगता
  • "कम हलचल" (reduce motion) चालू हो, 5 से कम कैटेगरी हों, या JS बंद हो —
    तब वो बिल्कुल नहीं सरकती, बस एक सामान्य खिसकने वाली पट्टी रहती है

3. ग़लत जुड़े चिह्न ठीक किए
---------------------------
रंग भरते ही कुछ ग़लतियाँ साफ़ दिखीं और सुधार दी गईं:
  • "कपड़े धोने का पाउडर" पर मिर्च की कटोरी दिख रही थी → अब साबुन
  • ख़ून की जाँचों पर तेल की बूँद / टॉफ़ी → अब टेस्ट ट्यूब
  • क्रीम, जेल, बाम, ORS → अब दवाई की शीशी
  • बिंदी, काजल → अब चमक; कोल्ड क्रीम, टैल्कम → अब शीशी
  • बोरी → अब बोरा; डिस्टेंपर → अब पेंट का डिब्बा

4. पन्ना ख़ाली क्यों है — अब साफ़ बता देता है
-----------------------------------------------
आपके यहाँ कैटेगरी नहीं दिख रही थीं। वजह कोड नहीं थी — **API बंद था** (या डेटाबेस में
seed नहीं चला था)। साइट हर API गड़बड़ी को चुपचाप निगल जाती थी, इसलिए पन्ना ऐसा दिखता था
जैसे दुकान में कुछ रखा ही न हो, और कारण कहीं नहीं दिखता था।

अब development में सबसे ऊपर लाल पट्टी आती है जो बताती है कि कौन-सी API कॉल फ़ेल हुई और
क्या चलाना है। ग्राहक को ये कभी नहीं दिखेगी (production में बंद रहती है)।

सही क्रम — तीन अलग टर्मिनल:
    npm install
    npm run db:migrate
    npm run db:seed -- --demo
    npm run dev:api        (टर्मिनल 1 — पहले ये चालू करें)
    npm run dev:web        (टर्मिनल 2)
API के बिना वेबसाइट ख़ाली ही दिखेगी।

6. एक फ़ैसला आपका बाक़ी है — होम पेज का वज़न
----------------------------------------------
होम पेज का HTML दबा कर 113 KB है; तय बजट 35 KB था। वजह: होम पर 20 कैटेगरी × 4 सामान
= 80 डिब्बे एक साथ भेजे जाते हैं। कोड धीमा नहीं है — सामान ज़्यादा है।

दो रास्ते हैं, आप चुनिए:
  (क) होम पर सिर्फ़ 6 मुख्य कैटेगरी × 6 सामान दिखाएँ (~40 KB) — बाक़ी कैटेगरी पट्टी और
      मेन्यू से खुलती रहेंगी। 3G पर पहला पन्ना क़रीब आधे समय में खुलेगा।
  (ख) जैसा है वैसा ही रहने दें — सब कुछ एक ही पन्ने पर, पर 3G पर थोड़ा भारी।

जब तक आप न कहें, मैंने आपका लेआउट नहीं बदला है।
