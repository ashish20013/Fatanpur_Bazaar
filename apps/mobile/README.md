# Fatanpur Bazaar — mobile app

One React Native app, role-based navigation (`CUSTOMER` / `DELIVERY_BOY` / `ADMIN` &
`SUPERVISOR` share one Staff shell). Only `src/` is source-controlled here — the native
`android/` project is generated once (see `android/README.md`) and never re-generated by hand
after you've made changes inside it.

## 1. One-time setup

```bash
# from the repo root
npm install                       # installs all workspaces, including packages/shared-types
cd apps/mobile
npm run build:types               # builds @fb/shared-types once so its dist/ exists

# generate the native android/ project — see android/README.md §1 for the exact commands
# and every AndroidManifest / native-module / google-services.json step
cat android/README.md
```

Copy `.env.example` → `.env` and fill it in:

```bash
cp .env.example .env
```

| Variable         | Meaning                                                                                     |
| ----------------- | --------------------------------------------------------------------------------------------- |
| `API_BASE_URL`    | API host, no `/v1`, no trailing slash. Emulator dev: `http://10.0.2.2:3000`. Real device on the same Wi-Fi as your dev machine: `http://<your-lan-ip>:3000`. **Production must be `https://`** — see the cleartext note in `android/README.md` §2. |
| `SOCKET_PATH`     | Must match the API's `SOCKET_PATH` env (default `/socket`).                                  |
| `SUPPORT_PHONE`   | Shown on the out-of-area "sorry" screen and in Profile.                                       |

`react-native-config` reads `.env` at **native build time** — editing it needs a rebuild
(`npm run android` again), a Metro reload is not enough.

Place Firebase's `google-services.json` at `android/app/google-services.json` — see
`android/README.md` §4. Push notifications silently no-op without it; nothing else breaks.

## 2. Run it

```bash
# terminal 1
npm run start        # Metro bundler

# terminal 2 — emulator running, or a device connected with USB debugging on
npm run android
```

`npm run typecheck` and `npm run lint` should both be clean before you build — the API
contracts this app calls come from `@fb/shared-types`, so run `npm run build:types` again
after pulling backend changes that touched shared enums/DTOs.

## 3. Build a release APK / AAB

Full signing setup (keystore generation, `gradle.properties`, `signingConfigs`) is in
`android/README.md` §5. Once that's done:

```bash
cd android
./gradlew bundleRelease    # android/app/build/outputs/bundle/release/app-release.aab — upload to Play Store
./gradlew assembleRelease  # android/app/build/outputs/apk/release/app-release.apk — direct install / testing
```

## 4. What's implemented

```
src/screens/customer/  Home Categories Search Product Service Cart Checkout
                        Orders OrderTracking Wallet Prescriptions Profile
src/screens/delivery/  Dashboard AssignedOrders OrderDetail Navigate
                        StartDelivery LiveLocation CompleteDelivery History Earnings
src/screens/staff/     Dashboard Orders DeliveryBoard Reports   (ADMIN + SUPERVISOR, permission-gated)
src/components/        + AddressForm, UpiPayment (shared between Checkout and Profile / Checkout)
```

Design notes worth knowing before you touch this code:

- **No map SDK is bundled.** `Navigate.tsx` hands off to whatever maps app is already on the
  phone (`Linking.openURL` to a Google Maps universal link); `LiveLocation.tsx` and
  `OrderTracking.tsx` show status text/dots, not a map view. This was a deliberate call for
  §3/§9 of `docs/BUILD_PROMPT.md` — `react-native-maps` plus tile rendering is real weight on
  a 2–4 GB Android phone for very little gain when the rider is a phone call away. If the
  owner wants an in-app map later, it's an additive change (a `MapView` inside those two
  screens), not a rework.
- **Rider location lifecycle** is driven from two places on purpose: `delivery/OrderDetail.tsx`
  and `CompleteDelivery.tsx` start/stop `LocationTracker` exactly at the accept/reject/pickup/
  complete/fail transitions (immediate), and `delivery/Dashboard.tsx` runs a `syncTracking()`
  safety-net poll (on mount, on focus, every 30 s, and on the relevant socket events) that
  re-derives "should be tracking right now?" from the server's own assignment list — so a
  killed-and-reopened app recovers correctly instead of leaving a stale foreground service
  running or silently not tracking.
- **Staff screens have no stack navigator.** `StaffNavigator` (see `navigation/StaffStack.tsx`)
  is tabs only, so `staff/Orders.tsx` drills into a single order by swapping its own body
  (`selected` state), the same pattern `customer/Categories.tsx` already used for its
  category → sub-category drill-down. Don't add a `Stack.Navigator` around it without checking
  that pattern first.
- **Permission gating in staff screens is UX only.** Buttons are hidden via
  `user.permissions` from `useAuth()`, but the server (`@RequirePermission` guards) is the
  real enforcement — every staff action still gets a normal `ApiError` + Hindi message if the
  server rejects it.
- Every user-facing string lives in `src/i18n/hi.ts`. If you add a screen, add its strings
  there rather than inlining Hindi text.

## 5. Left for the owner

- **`npm install` was never run in this sandbox** (no network access) — the two packages
  added for `Prescriptions.tsx`, `react-native-document-picker@9.3.1` and
  `react-native-image-picker@7.1.2`, are declared in `package.json` but not yet installed or
  native-linked. Run `npm install` and rebuild once you have network access; if either
  package's actual API differs from what's called in `Prescriptions.tsx`
  (`DocumentPicker.pick({ type: [...] })`, `launchCamera(...)`), fix that call site against
  the installed version's real typings — it could not be verified against real `node_modules`
  here.
- **The native `android/` (and `ios/`) projects don't exist yet** — generate them per
  `android/README.md` §1, then re-apply that document's manifest/native-module/signing steps.
  This only has to be done once; after that, `android/` is a normal part of the repo.
- **Firebase project + `google-services.json`** — create the Firebase project, register the
  Android app under whatever `applicationId` you chose, download the file, place it per
  `android/README.md` §4.
- **Release keystore** — generate it per `android/README.md` §5 and store it (and its
  passwords) somewhere safe outside git; losing it means the Play Store listing can never be
  updated again under the same app.
- **Exact business config** (support phone, UPI VPA, coordinates, village list) is owned by
  the top-level `docs/NEXT-STEPS.md` in the monorepo, not duplicated here — this app just
  reads it from the API (`/service-area/villages`, `/payments/upi-details/:orderNumber`,
  `SUPPORT_PHONE` in `.env`).
- **Play Store listing** (screenshots, privacy policy URL, content rating, data-safety form)
  — not something code can produce; the privacy policy text itself lives in the website's
  legal pages per `docs/BUILD_PROMPT.md` §11.
- **No `tsc`/`eslint` run was possible in this sandbox** (no `node_modules`, no network) —
  run `npm run typecheck` and `npm run lint` as the very first thing after `npm install`
  succeeds, before doing anything else with this code.
